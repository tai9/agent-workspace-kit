# Prior findings

What has already been measured, tried, reverted, or deliberately
decided — so no persona re-discovers it, contradicts it unknowingly, or
proposes what was already rejected. **Stale by design: every entry
carries a date, and any persona that proves an entry wrong fixes it in
the same engagement.**

Adoption seeds this from: existing audit/analysis docs, decision records
in commit/PR messages and migrations, the owner's memory (interviewed),
and dashboards' known caveats.

Format — one entry per finding:

```
## <short title>  (<date>)
What was measured/decided, the number or decision, the source, and what
would invalidate it. If a feature/limit/behaviour was deliberately
removed or disabled: say so and link the reason — "absent" and "removed
on purpose" are different facts.
```

Standing lists worth maintaining here: events that have never fired,
event names that do not exist despite appearing in docs, numbers commonly
quoted from memory that drift (prices, tier limits).
